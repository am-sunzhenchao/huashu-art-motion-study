1背景

1.1 缘起

这个 skill 起于一次真实复刻：2026-10-04，X 用户 Tak（@cherry_mx_reds）发布了一支 15 秒的「Art History Speedrun」，用 16 个艺术时代讲完艺术史。作者花叔没有录屏或逐帧 AI 生成，而是把这支片子拆解成机制，用代码逐帧重画——HTML5 Canvas 渲染、headless Chromium 逐帧驱动、ffmpeg 合成。复刻成功后，方法论沉淀为可复制的工程（scripts/engine/），并沿三个方向扩展：35 种艺术风格配方、YouTube/科技/财经解说片的 8+1 种动画语法、口播整片参考代码。

1.2 它要解决的问题

AI 参与做视频，反复栽在同样的坑上。SKILL.md 把最常见的失败总结成「六种做坏方式」，其中一半是生成式视频的通病：

病灶典型症状拦截手段
翻页式 PPT固定页眉、要点逐条淡入、每镜同一个镜头动作、结尾居中金句卡；作者原话「完全是放 ppt 的感觉」storyboard_lintfilm_gate
一眼 AI 味蓝紫渐变底、深紫星空、霓虹青紫——「这种非常 ai slop」；每镜换画风的拼贴色板锁 + 蓝紫门禁
死背景 / 空画面大面积纯色或星空底不变，只有中间一小块在动空画面门禁
没有具体的物抽象概念只写成字和图标，写不出一行"物在做什么"镜头表 lint
有真实素材却用代码画截图、照片、原文本可满幅使用，却被代码重新绘制冲淡可信度窄桥规则
照搬示范示范片、样例 spec 的构图与素材原样进成片窄桥规则

更深一层的问题是：agent 做视频没有工程化的质量关。写代码可以跑测试，做视频的 agent 却常常"渲完就交"。这个 skill 把软件工程的门禁思想搬进视频管线：lint（镜头表）→ CI（qa.py 量化验收）→ 发布门禁（film_gate 红绿灯 + deliver.py 指纹化交付说明）。

1.3 定位

一句话定位：这是一个 agent skill 包（符合 agent skill 规范的 SKILL.md + references/ + scripts/ 结构），让 coding agent 不装任何前端构建系统，纯用代码产出可交付的动画视频；画什么、怎么画的知识以卡片文档形式喂给 agent，渲染与门禁全部脚本化。

技术栈刻意求简：渲染引擎是 vanilla JS（ES5 IIFE、Canvas 2D），CLI 工具是 Python 3（PEP 723 内联依赖，经 uv 运行），外部依赖只有 uv、ffmpeg/ffprobe、Playwright Chromium 三个。无 npm、无打包器、无 Node。

2目标

2.1 核心目标

  • G1 纯代码产片：从零到成片全程可由 agent 用代码完成——拆解参考、设计镜头、渲染、合成、质检、交付，每个环节都有 CLI 入口。
  • G2 知识可传承：把"导演对镜头/画风的判断"和"每种风格/语法的实做参数"写成结构化卡片（35 风格配方 + 9 动画语法 + 12 篇方法文档），agent 按需检索，而不是靠模型即兴发挥。
  • G3 质量可验收：所有质量要求落成脚本门禁——镜头表 lint、qa 量化、成片红绿灯、指纹化交付说明；红灯不交付。
  • G4 结果可复现：确定性契约——所有随机播种，同一时刻渲两次逐像素一致；clip 时长 frame-exact。

2.2 非目标

  • 不做实时/交互式动画编辑器，只做离线逐帧渲染管线。原因：
    • 确定性靠「时间 → 帧」的纯函数成立：引擎契约是 renderFrame(t)——同一个 t 永远画同一帧（engine.js 首行注释），qa.py 用冷热双渲染逐像素比对来验收。实时/交互渲染会引入鼠标位置、帧率波动等不可控输入，确定性立即失效；整套「同 t 同像素」的架构前提就是时间完全由外部驱动。
    • 与 coding agent 的工作流不符：这个 skill 让 agent 纯用代码产片，agent 无法拖动时间轴、移动对象。实时编辑器需要图形界面与人工介入，而 agent 的「编辑器」就是代码本身——改参数重渲，配合 --stills 抽帧检查就能达到同等的反馈速度。
    • 技术栈刻意求简：无 npm/Node、ES5 IIFE 开箱即用（3.4 决策）；任何带 GUI 的编辑器都会引入构建系统、运行时与更大故障面。
    • 质量门禁全是批处理式的：lint → qa → film_gate → deliver 全部按离线成片量化验收（运动帧占比、空画面、蓝紫底），实时渲染产物走不通这条门禁链。
  • 不内置语音与生图能力：语音复刻与图片生成按需配置（策略默认 ask），凭证保存在安装目录之外，公共默认不绑定作者声音。原因：
    • 宿主已有，不必重复内置：语音与生图是宿主 agent（Claude Code/Codex/Kimi）自带的能力，skill 只做「能力配置 → 宿主动作 → 产物验收」的接入（capabilities.py、images.md），内置会在各宿主间重复造轮子。
    • 凭证与隐私不外流：配置（含私人音色、API 凭证）放安装目录之外且只存变量名/文件引用、不存 Key 值；公共包不携带作者声音，任何安装者拿到同一份干净模板——这是 3.4「凭证与默认配置分离」决策的直接体现。
    • 授权与合规：云调用/付费/训练均为一次性的显式授权（allow flags + deny policy），默认 ask 不自动获准，防止 skill 未经用户同意触发付费 API。
    • 保持核心引擎干净：语音（ffmpeg/requests）与生图（Pillow）是可选依赖，缺了照样产片，不拖累引擎与门禁。
  • 不用代码画人脸、机器人，也不给物加脸——角色由 AI 生帧 + 代码合成（B/C 两法），或只出手和背影。原因（出自 references/角色精细度.md，作者被多支片子逼出来的结论）：
    • 一眼 AI 味，全片被拖垮：圆头豆豆眼小人、白壳蓝面罩机器人、长了脸的金币是"AI 默认角色"，观众第一反应是「AI 做的」——作者原话「颜色和人的风格形象都有些 ai slop」；粗糙的角色比没有角色更差。
    • 代码画脸达不到交付线：帧库角色要过 8 条（剪影认得出、骨架比例、手能真的握物、两层明暗、三处材质细节、表演具体到"皱眉看手机"、与背景同画风、多镜五官一致），Canvas 参数化拼装的形状几乎必挂，短板正在「表演具体」与「前后一致」。
    • 给物加脸是把"讲清楚"偷换成"卖萌"：表情包式的脸不增加信息量；物可以用形状与动作（冷时挤成一团）、尺度、对比、真实素材来"演"，不加脸照样讲活。
    • 规则被工程化强制：y4 无帧库启动即失败、lib/toon.js 代码角色停用、lint 与独立审片都会拦；例外是全片主角为拟物角色（如一支画笔）时，过「三方向硬门」并由用户挑定造型后可以有脸。
  • 不做逐像素复刻服务——复刻是学机制（场景、运动、转场规律），不是描图。原因：
    • 逐像素没有信息增量：复刻的全部价值在五层机制（固定骨架、活的画、签名转场、节拍网格、叙事锚）——02 号明言「不要逐像素复刻原片。复刻是学机制的手段，交付物是你理解后的版本」（原片骨架换角色、换题材重构图）。
    • 拆解工具量的是机制不是像素：analyze/breakdown.py 产出的逐帧灰度差、BPM 网格、运动热图、转场接触表全是「规律与参数」，不是帧拷贝；这套拆解方法可迁移到任何新题材，像素没有这种迁移性。
    • 代码复刻实质上做不到、也不该做像素级拷贝：逐像素一致只能靠录屏/截图搬用原片帧，那就成了素材搬运而非代码产片，既无工程价值也越过版权边界。

2.4 制作成本观察

以「参数风格对比」工程实测（35 支、10s@30fps、统一镜头表，2026-10-24）为样本：一支 10 秒样片约 50 分钟产线时间，纯渲染只占 1–3 分钟，其余几乎全部花在「写重构图场景」与「门禁迭代」上。

环节耗时占比说明
写重构图场景 scenes/s<id>.js≈ 50%每支约 700 行新实现（35 支共约 26,000 行）：读风格卡 → 对照原版渲染器 → 为题材重新构图 → 三拍动作／母题循环／数字画法／播种。是智能密集型主耗时。
门禁迭代「改→渲→查」≈ 33%lint → 静帧 4 张＋查帧.py 数字读帧（无视觉环境核对构图／色板／元素在位）→ qa.py 冷＋热＋再渲逐像素比对（每段渲 300+ 帧 ×3 遍）→ 出片。实测梵高 2 轮＋1 轮补帧（getImageData 告警，拆三张画布后 qa 全绿）；多数风格类似或更多轮。
出片＋配音混流≈ 15%10s@30fps 共 300 帧渲染，＋ChatTTS 口播（LUFS 归一化、三拍节拍对位）＋ffmpeg 混流入成片。
文档回检少量分镜 .md（含自检数字）、qa 记录核对、ffprobe 核验时长帧数。

token 成本：量级 4–8 万/支（估算）

  • 输出约 2–3 万：700 行 × 每行 20–35 token——固定成本，不算爆炸。
  • 输入通常 > 输出：读风格卡（约 1–2K）＋对照原版 scene（500–900 行，约 1–2 万）＋每轮迭代把查帧／qa／lint 结果与历史重新读入；迭代轮数直接让输入翻倍（梵高 2 轮＋补帧核验）。

省成本杠杆（按收益排序）

  • 母版骨架复用：同题材多风格时先做一支三拍母版，其余只换渲染器／色板／母题动作，代码量可从约 700 行压到 150–250 行；
  • 先 --stills 迭代、后全片 qa：构图与色板用 4 张静帧核检过线后再跑全片 qa，避开冷热双渲的高成本环节；
  • 独立会话／轨道档分档：每支独立上下文，或按 SKILL.md 轨道档「只读点名文件」，避免历史与无关文档堆积。

3概要设计

3.1 总体架构：四层结构

skill 的四个层次自上而下是"知识 → 判断 → 工具 → 引擎"，层间只通过文档约定与 CLI 接口耦合。

层组成职责与接口
入口层SKILL.mdagent 的唯一入口：任务路由表（用户说什么 → 读哪份文档）、模型分档（开阔档/轨道档）、导演要求、六种做坏方式、验收与回流协议、版本检查协议。
知识层references/12 篇方法文档 + 风格配方 35 卡 + 动画语法 9 卡 + 模板规范（镜头表、色板、镜头语言、角色精细度）。是 agent 的"大脑外挂"，全部按需读取。
工具层scripts/*.pyCLI 工具链：创作门禁（storyboard_lint、qa、subzone_gate）、交付门禁（film_gate、deliver）、可选能力（capabilities/koubo/images）、拆解（analyze/breakdown）、素材工具、发布审计（check_release）。
引擎层scripts/engine/可整体复制的渲染工程：双模式运行时（engine.js / clip.js）、36 个风格场景、17+ 绘制库、转场库、渲染器 render.py。开新片 = cp -R 到项目里改。

3.2 双管线渲染

Film 与 Clip 两种模式服务不同制作形态，共享同一渲染内核（本地 HTTP + 无头 Chromium + ffmpeg）与同一套绘制库。

Film 模式（风格长片）Clip 模式（解释类片段，主产线）
输入eras.js 段落表（id、eighths|dur、transition、计数卡）JSON spec：{grammar, duration, fps, width, height, safe, theme, data, cues[]}
时间轴BPM 八分音符节拍栅格（默认 128BPM），可写秒级 dur线性秒轴，cue 以 at 触发，无段落表无转场
运行时engine.js：t → frame，离屏缓冲 A/B 做转场clip.js + clips/<grammar>.js 注册进 CLIPS[grammar]
画面单元scenes/<id>.js 的 draw(c, lt, t)语法库内建版式（中心物、桌面拼贴、白板、豆子角色……）
调用render.py --film <名> / --solo <id>render.py --spec 片段.json（--alpha 出 ProRes 4444 透明）

3.3 核心概念模型

  • 镜头表（<项目>/镜头表.md）：轨道档工作流的源头，一行一镜——时间段、物（名词）、动作（动词）、镜头（停/缓推/拉远/横移/快推/砸入/切）、屏上字、做法；表前锁画风、色板、角色。lint 不过不许写代码。
  • spec 契约：口播管线与引擎的稳定接口。8 选 1 的 grammar + 时长精确的 cues[]；at 是"揭开那一帧"（数字类是落定时刻），kind 写错静默不画。
  • 门禁（gate）：可计算的验收阈值。镜头表 lint → qa 量化 → film_gate 三红灯 → deliver 复制成片并写指纹化交付说明。红灯链条式阻断：lint 红灯不许写码，gate 红灯不出片。
  • 经验回流：做完一支，把"做对的事"（做法+证据+为什么+何时用）写进 07-正面经验.md，新风格补配方卡，新坑写进对应 reference 的「踩过的坑」，CHANGELOG 记一行——知识层因此随使用变厚。
  • 模型分档：对使用方 agent 的能力分级——开阔档（强模型，可自由组合库、自写渲染器）与轨道档（照六步流程走，只读流程点名的文件）。同一 skill 兼容不同水平的使用者。

3.4 关键设计决策

决策理由被放弃的替代
无构建系统的 ES5 IIFE 引擎skill 要在任意机器开箱即用；headless Chromium 直接加载，无 transpile 环节，故障面最小npm/webpack/ES modules（引入 Node 工具链依赖）
逐帧截图而非实时录屏时间 t 完全由外部驱动 → 确定性契约可成立（同 t 同像素）；可 --stills 抽帧检查MediaRecorder 实时录制（帧率不可控、不确定）
像素流走 ffmpeg stdin 管道base64 PNG → pipe → H.264，避免落盘中间帧；GOP=fps 支持管线按秒 seek先出 PNG 序列再合（IO 翻倍）
JSON spec 作为 clip 唯一契约口播管线（外部程序）可编程对接：从词级时间戳算 cue，不碰 JS让管线直接写 JS（强绑定、易出错）
知识卡片化（35+9 卡）参数、坑、质量短板全部结构化沉淀，agent 按需读一页就能开工长篇教程文档（上下文成本高、检索难）
门禁前置、红灯不出片把"审片"从主观判断变成可计算阈值，agent 无法绕过交付纪律靠 agent 自觉或人工抽查
相机只由时间决定推拉移都是同一世界画布在不同相机下重画，放大 60 倍也不糊（矢量重绘），转场中上一镜可继续推缩放位图/双层画布叠加
凭证与默认配置分离私人音色/参数放安装目录外，skill 升级不覆盖、公共包不携带作者凭证配置进仓库（泄漏 + 升级冲突）

4详细设计

4.1 入口层：SKILL.md 的路由与分档

SKILL.md 不是说明书，而是给 agent 的执行程序。它包含五类可执行指令：

  • 模型分档：先自判档位。开阔档（强模型）读全文并允许自写渲染器；轨道档只走一条 6 步流水线，且每步只读点名的文件——控制弱模型的上下文与自由度。
  • 任务路由表：8 行「用户说的 → 做什么 → 读什么」的映射，覆盖复刻、风格动画、口播艺术片、配乐、角色、风格委托、长卷穿越、解说动画八类任务。
  • 导演要求：镜头是标点（看得清就不动；过渡用缓的、重音才用快的；有来有回）、画风服务内容（有真实素材素材就是主画面；一片一套画风一套色板管到最后一帧）。
  • 窄桥硬规则：人用 AI 生帧不画人脸、示范只学做法不搬内容、复刻学机制不逐像素、三方向硬门、确定性、独立审片。
  • 验收与回流协议 + 版本检查协议（见 4.7）。

为什么把「先分档」放在最前

分档判据是模型能力（SKILL.md 原文：Opus 5.5 级或更强＝开阔档；其它模型、或判断不出自己是谁＝轨道档），分档决定读多少文档与拿多少自由度。

  • 控制上下文预算：全量 references 数万字（35 风格卡＋9 语法卡＋12 方法文档＋09 号 54K）。强模型读全了能检索复用；弱模型读完就把上下文挤爆，「读得越多、做得越差」。轨道档"只读点名文件"本质是用流程代替记忆。
  • 自由度必须和能力匹配：六种做坏方式大多是"自由发挥"的产物——照搬示范构图、顺手换画风、写 Math.random() 破掉确定性。轨道档把自由度全剥走，判断力从模型手里拿走，交给可计算的门禁（lint 红灯拦 → qa 量化 → deliver 非零退出）。
  • 分错档的代价不对称，所以保底单向：低估无害（轨道档零发挥也能交过门禁的片，只是平庸）；高估致命（自觉开阔档自由发挥，翻车率高）。所以"判断不出自己是谁"强制归轨道档——把失败模式前置拦截，而不是等成片坏了再修。
  • 挂钩核心目标：分档让"质量可验收（G3）"不依赖用哪个模型——任何水平的使用者走同一套门禁，产物可复现（G4）、知识可传承（G2），skill 的价值不押在某个强模型身上。
命名的意象：「轨道档」＝有轨电车——路径固定、不会脱轨、顺着走必到站，但到不了轨道以外的地方；rail 兼有"护栏"义，正是 lint/qa/deliver 脚本在当护栏。「开阔档」＝一片开阔地——没有轨道，凭本事走；对应 SKILL.md「开阔地」一节的原话「当起点，不当配额」。「档」＝挡位：轨道档是低速稳定挡，谁挂上都能安全到终点；开阔档是高速挡，只有驾驭得了的才挂得住。一对名字把"能力分权"翻译成画面：一条保底的路 vs 一片凭本事走的地。

4.3 引擎层

4.3.1 渲染器 render.py（统一入口）

流程：起本地 HTTP 服务（spec 素材经白名单 /__file__/ 提供）
  → 无头 Chromium 打开 index.html / clip.html
  → 对每帧 evaluate：await prepare(t); renderFrame(t); canvas.toDataURL(png)
  → base64 解码 → 写 ffmpeg stdin（image2pipe, -framerate fps）
  → H.264 yuv420p（GOP=fps，按秒 seek 不冻帧）；--alpha 时 ProRes 4444
模式：--film <名>（读 eras_<名>.js 整片）｜ --solo <id>（单段试渲）
     --spec clip.json（参数化片段，帧数 = round(duration×fps)）
     --stills 0.5,2（只抽静帧检查）｜ --width/--height 覆盖画幅（竖屏 1080×1920）

页面报错（语法文件出错、图片/视频帧不存在、spec 缺字段）会设置 window.__bootFailed，render.py 感知后非零退出、不出片——"素材缺失一律报错，不画空白帧"是引擎的硬规则。

4.3.2 Film 模式运行时

  • eras.js 段落表：每段 {id, eighths|dur, transition, clip?}；window.BPM 改节拍、window.PUNCH=0 关拍点冲击、window.FILM_SIZE 定画幅。
  • engine.js：t → frame；BPM 八分音符栅格生成时间线；离屏缓冲 A/B（转场中上一镜按时间继续推相机，zoomThrough 的 live:true 由此实现）。
  • scenes/<id>.js：每个风格一个文件，实现 draw(c, lt, t)（lt 为本段局部时间），登记进 eras.js；两位数字编号与风格配方卡对应。
  • transitions.js：转场库，每个函数从两段画面提取时代签名形式元素；解说语法另有 13 个专用转场（lensReveal、matchCut、fillZoom、bands、blurPush…）。

4.3.3 Clip 模式运行时与 spec 契约

clip.js 同步 XHR 拉取 clips/<grammar>.js 并 eval 注册到 CLIPS[grammar] = { init?, draw, safe? }；spec 由 render.py 注入 window.CLIP_SPEC。关键契约：

字段约定
at秒，必填。「揭开那一帧」：元素在 t=at 这帧首次可见，动画内部从 at−1/fps 起算；例外：number 的 at 是数字落定时刻
kind必填。写了语法不认的 kind 不报错、什么都不画——对着语法卡写
safe{top,bottom,left,right,fill?}，让开字幕带；8 语法均接 top/bottom（语法对象 safe:true），left/right 尚无语法排版
theme一支片所有 spec 同一个：色板名（paper/poster/ink/navy/bauhaus/snow/wood/chalk）或 6 键对象 {bg,surface,ink,sub,accent,accent2}；色值非法启动失败
number只有 t2/t3/y5 认：data.value 从 0 滚到 value（expoOut），prefix/suffix/decimals，at≥0.9（y5 为 0.7）
时长上限单片段 ≤8s，超时开头结尾各打一次警告（口播管线有合法长片段）
素材cue.image / frames（帧序列目录或数组）/ data.character（y4 帧库）；路径相对 spec，白名单经 spec_assets.py 校验改写，缺失拒绝渲染

8 种语法一览：y1 Kurzgesagt 扁平科普（中心物+卫星节点+尺度穿行）、y2 Vox 拼贴（真实材料桌面+红线荧光笔）、y3 白板手绘（说一句写一句）、y4 storytime（豆子角色，需自备 AI 帧库）、y5 动态文字（一 cue 一页）、t1 3b1b（黑底形变讲机制）、t2 发布会界面（截图满幅推近）、t3 财经图表（坐标系先出、数据诚实）。y6 讲解员式提供语法卡与整片参考代码（reference_films/spacex/），尚无参数化片段。

4.5 质量门禁与交付链

轨道档六步流水线，三处红灯点层层拦截。

门禁阈值与判定后果
快速运动帧占比<0.035 红灯（整片几乎没有镜头内运动 / 翻页 PPT 感）；<0.06 黄灯（推近太密，用正常速度看一遍）红灯
空画面成片中段连续 ≥0.3s 近乎纯色或整帧无边缘的空画面（给时间码）；片段再短也拦红灯
蓝紫底蓝紫帧占全片 ≥30% 红灯；题材本身要蓝紫时 --allow-blue-purple "理由" 降黄，理由写进交付说明红灯
字幕区入侵浅底无字幕成片，图形进入字幕带（纹理底不适用）黄
门禁的边界：门禁只拦得住可计算的三样；页框、米底小图、前紧后松、每镜换画风的拼贴拦不住——所以交付说明要求人工段补「六种做坏方式」自查与逐镜 qa 结论，且运镜顺不顺必须用正常速度把成片看一遍。静止多不是病（解说片本有大段停住），静止类数字不用于判定。

交付产物：output/成片.mp4 + 交付说明.md。说明书的事实段（时长、门禁各项、最差 30 秒窗口、qa 结果、有没有审片）由脚本带指纹写入，不许手改；制作者只在「制作说明」段补语法用法、逐镜 qa、黄灯理由与自查。派了独立审片的，审片 agent 只看成片、结论写进 <项目>/审片/*.md，deliver.py 只认这个目录。

4.6 测试与 CI

  • Python stdlib unittest，无 pytest；渲染测试是集成型的：真实启动 render.py + Playwright，用 Pillow 断言像素；uv/Playwright/ffmpeg 缺失时自动 skip。
  • 覆盖：film_gate 三门禁各自有专项测试（慢/快/平滑合成片、空白片、蓝紫片）；storyboard_lint 绿灯/红灯理由；clip 的 theme 解析与 y4 无帧库启动失败；本地服务定义；能力配置；发布审计。
  • JS 引擎无单元测试——质量由 qa/film_gate/deliver 在交付时强制，确定性契约用双渲染兜底。
  • CI（GitHub Actions）：job contracts（ubuntu，Python 3.10/3.12，unittest + check_release）+ job windows-render（Windows 冒烟：渲 09_postimp 静帧 + qa.py --fps 5）。

4.7 版本检查与发布

  • 版本检查协议：skill 使用时读 .last-update-check（日期+结果）；到期（ok 30 天 / failed 7 天）才 git ls-remote --tags origin 'v*' 比对 metadata.version；远程更高只提醒不自动更新，off 可永久关闭。只写这一个文件，不上传数据。
  • 发布卫生：release-manifest.json（sha256 清单）+ check_release.py 审计 git 对象而非磁盘文件——磁盘上删掉的文件只要进了历史就查得出，防凭证先提交后删除的漏检。

5二次开发注意事项

5.1 新增一种艺术风格

  1. 写 scenes/NN_<id>.js（编号与 风格配方/NN_<id>.md 一一对应），实现 draw(c, lt, t) 并登记进 eras.js（gallery 则登记 eras_gallery.js）。
  2. 配方卡必写：实做参数、母题动作、签名转场、当前质量与短板——INDEX 明言"下一次做到它时先超越短板"。
  3. 每幕一个主动作 + 2 个母题循环，画要一直活；随机全部播种。
  4. 35 张样片共用同一房间构图是速通片的机制，不是风格的构图——新题材要为题材重新构图，不许照搬。
  5. 完成后走回流：卡补进 INDEX 两表之一（材料层/时代标本），CHANGELOG 记一行。

5.2 新增一种动画语法

  1. 写 clips/<前缀>_<名>.js，注册 CLIPS[grammar] = { init?(ctx), draw(c,t,ctx), safe?: true }；前缀沿用 y1–y6 / t1–t3 语义或另立。
  2. spec 给了 safe 而语法没接（对象里没写 safe:true）时 clip.js 会 console.warn——按 ctx.box 排版，别学一半。
  3. 同步写 references/动画语法/<语法>.md（一句核心语法、镜头基调、起手必查、认哪些 cue kind）+ demos/ 示范片 + examples/ 样例 spec。
  4. 版式遵循退路原则（见 5.5）；步进动画从 cue 的 at 起算：MO.step(t-at, 12)，否则元素会早最多一格露出。

5.3 spec 扩展的坑

  • 静默 kind：语法不认识的 kind 不报错不画——这是有意设计（cue 公共字段跨语法复用），扩展字段时必须同步语法卡与 09 号文档，否则下游写了也不生效。
  • camera:"snap" 的位置：快推开关必须写在 spec 顶层 data（{"data":{"camera":"snap"}}）；写在 cue 的 data 或顶层同级都不生效也不报错。
  • number 不继承：t3 的 spec 级 decimals 只管柱标签，number cue 要小数得自己再写。
  • safe 的 left/right 未接：目前只有 top/bottom 参与排版，left/right 仅被 fill 涂色。
  • rect 目测偏移 20–30%：t2/y2 的 highlight rect 要先 --stills 渲一张核对；竖屏一句话跨两行就拆成两个 highlight 各对一个关键词。
  • 8 秒上限：单片段超 8 秒只警告不报错（口播管线有合法长片段），自用时拆镜。

5.4 确定性与性能契约

  • 所有随机必须经 U.rng 等播种工具；新代码引入 Math.random()/未播种噪声会打破冷热双渲一致性，qa 直接报红。
  • 复用离屏缓冲时注意残留：t2 曾因复用缓冲带上一帧残留导致同一时刻渲两次差 1 色阶——改缓冲复用要清底。
  • 两层帧率是刻意的（相机平滑、元素 12fps 步进 / 角色 24fps），别为了"丝滑"统一成 60fps——全丝滑像企业宣传片，全步进会晃。
  • 环境层（星闪、粒子）只读片段时间不读全片时间，避免片子在时间轴上的位置影响相位（历史上 T2.PHASE 坑）。

5.5 版式退路原则

凡是「放不下」的地方都要有退路：先缩字号、再折行、再让位（旧元素上卷淡出），最后才告警。只在样例长度上调好的版式，一碰真实口播就破——y1 标题被切、y3 说明出画、y4 打字溢出气泡、t3 副标题出画，全是终审在真实长度的 spec 上抓出来的。新语法交付前必须用横屏、竖屏、真实长度、边界、alpha 各渲一遍。

5.6 字体与素材

  • 新增字体走 font_subset.py 抽 GB2312 子集，输出 woff（不是 woff2）——引擎的 U.loadCmaps 只解 WOFF1/TTF；许可写进 lib/fonts/LICENSES.md。
  • 全角空格在普惠体里字宽为 0 会粘字，font_subset.py 抽子集时自动设为与「一」同宽，旧文件用 --fix-widths 修。
  • 思源黑/宋（NotoSansSC/NotoSerifSC）只含三支示范片用到的字，新内容别用；系统字体（Menlo、宋体）不进成片。
  • spec 内素材路径相对 spec 文件，只有点名的文件经 /__file__/ 白名单提供；新语法读素材一律用 MD.*，缺失报错不画空帧。

5.7 发布、升级与文档同步

  • 所有新 Python 脚本沿用 PEP 723 内联依赖 + uv run，不要引 requirements.txt。
  • 用户私人配置（音色、参数、凭证）在安装目录外，升级不得覆盖；新增能力默认 ask，不会自动获准。
  • 发版前跑 check_release.py check 并更新 release-manifest；敏感信息看 git 历史不只看工作区。
  • 实际与文档不符时以实际为准，然后把文档改对——交付说明的事实段带指纹不许手改（--verify 校验）；SKILL.md/09 号文档里的参数与阈值改动要同步 docs/agent/ 四份开发文档。
  • 每做完一支片的回流义务：正面经验（做法+证据+为什么+何时用）进 07 号，新坑进对应 reference 的「踩过的坑」，新风格补卡更新 INDEX，CHANGELOG 记一行。
